# Nexa AI Platform

دستیار سازمانی فارسی و راست‌چین. این مخزن از LibreChat در کامیت `f4154b649efa37e1345ccc517a4d8d1ed2178c82` منشعب شده است. فایل LICENSE و اعلان‌های بالادستی حفظ شده‌اند. کد Nexa در پوشه `nexa/` قرار دارد.

## راه‌اندازی

از ریشه مخزن اجرا کنید.

```sh
docker compose -f compose.nexa.yml up -d --build --wait
docker compose -f compose.nexa.yml exec nexa python -m django createsuperuser
```

چت در http://127.0.0.1:8080 و مدیریت در http://127.0.0.1:8080/admin/ است. با مدیر وارد شوید و در پنل «تنظیمات سازمان» را باز کنید. پیش‌فرض سامانه «فقط دانش» است. یک مدخل سؤال و پاسخ بسازید و سؤال ثبت‌شده را در چت بپرسید.

برای اجرای محلی با Python 3.11 یا جدیدتر، در پوشه `nexa` اجرا کنید.

```sh
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
export DJANGO_SETTINGS_MODULE=nexa.settings
python -m django migrate
python -m django createsuperuser
python -m django test nexa
python -m django runserver 127.0.0.1:8080
```

در اولین اجرا، Nexa یک کلید ثابت در پوشه داده می‌سازد. در Docker این پوشه در حجم داده قرار دارد. اگر `NEXA_SECRET_KEY` را خودتان تنظیم می‌کنید، مقدار آن را بین اجراها ثابت نگه دارید. تنظیم `NEXA_TIME_ZONE` به‌صورت پیش‌فرض `Asia/Tehran` است. شمارش روزانه و ماهانه از نیمه‌شب تقویم میلادی در همین منطقه زمانی محاسبه می‌شود. زمان بازنشانی در رابط به شمسی نمایش داده می‌شود.

### استقرار پشت پروکسی و امنیت ورود

برای انتشار روی دامنه پشت پروکسی TLS، در `nexa/.env` مقدار `NEXA_ALLOWED_HOSTS` را برابر دامنه، `NEXA_CSRF_TRUSTED_ORIGINS` را برابر آدرس کامل مانند `https://nexa.example.com`، و `NEXA_PROXY_SSL_HEADER=1` و `NEXA_HTTPS=1` قرار دهید. پروکسی باید سرآیند `X-Forwarded-Proto` را تنظیم کند. پاسخ‌ها از مسیر `/stream/` به‌صورت تدریجی (Server-Sent Events) ارسال می‌شوند. Nexa سرآیند `X-Accel-Buffering: no` را می‌فرستد؛ در پروکسی‌های دیگر بافر کردن پاسخ را برای این مسیر خاموش کنید. هر پاسخ در حال دریافت یک رشته gunicorn را اشغال می‌کند، پس حداکثر پاسخ هم‌زمان برابر `NEXA_WORKERS × NEXA_THREADS` است (پیش‌فرض ۱۶). آدرس `127.0.0.1` همیشه برای healthcheck مجاز می‌ماند.

پس از `NEXA_LOGIN_MAX_ATTEMPTS` تلاش ناموفق (پیش‌فرض ۵) در `NEXA_LOGIN_WINDOW_SECONDS` ثانیه (پیش‌فرض ۹۰۰)، ورود آن حساب موقتاً مسدود می‌شود و درخواستی به AD ارسال نمی‌شود تا حساب دایرکتوری کارمند قفل نشود. محدودیت بر اساس IP با `NEXA_LOGIN_MAX_ATTEMPTS_PER_ADDRESS` فعال می‌شود و فقط وقتی مناسب است که Nexa آدرس واقعی کاربر را ببیند. خطاهای مدل، AD و خطاهای داخلی در خروجی کانتینر (`docker compose logs nexa`) ثبت می‌شوند. پرسش ناموفق از سهمیه کم نمی‌شود. فهرست کامل متغیرها در `nexa/.env.example` است.

## اتصال‌ها

- **مدل** — از «مدل‌ها» در پنل مدیریت، آدرس کامل سرویس سازگار با OpenAI، شناسه مدل و کلید API را ثبت کنید. مثال آدرس `https://api.openai.com/v1/chat/completions`. مدل پیش‌فرض و مجوز انتخاب را در سیاست ثبت کنید.
- **LibreChat** — پس از ساخت Agent و دریافت کلید API از LibreChat، آدرس `/api/agents/v1/chat/completions`، شناسه Agent و کلید آن را در فرم مدل Nexa ثبت کنید. برای Hybrid یک Agent بدون ابزار، حافظه و فایل‌های مستقل انتخاب کنید. [API اجرای Agent](https://www.librechat.ai/docs/features/agents_api)
- **AD** — در «تنظیمات سازمان»، حالت ورود، آدرس `ldaps://`، Base DN، Bind DN، رمز حساب اتصال و در صورت نیاز متن گواهی عمومی CA را وارد کنید. کاربر دایرکتوری را ابتدا در «کاربران» بسازید و سپس در «هویت‌های دایرکتوری» به نام حساب AD نگاشت کنید. ورود مدیر محلی از مسیر `/admin/login/` برای بازیابی دسترسی در دسترس است.

رمز AD و کلید مدل در پایگاه داده رمزنگاری می‌شوند و فرم مدیریت آن‌ها را بازنمایش نمی‌دهد. برای حفظ مقدار قبلی، کادر رمز را خالی بگذارید. تنظیمات ذخیره‌شده در پنل بر متغیرهای محیطی و مسیر گواهی قدیمی مقدم‌اند. پاک کردن مقدار پنل، تنظیم قدیمی را در صورت وجود دوباره فعال می‌کند. هنگام پشتیبان‌گیری، کلید ثابت Nexa را همراه پایگاه داده حفظ کنید تا مقادیر رمزنگاری‌شده پس از بازیابی قابل خواندن باشند.

### اجرای LibreChat کنار Nexa

برای اتصال یک Agent در محیط محلی، فایل `nexa/librechat.env.example` را به `nexa/librechat.env` کپی کنید و کلیدها را با `openssl rand -hex 32` برای `CREDS_KEY` و هر دو کلید JWT، و با `openssl rand -hex 16` برای `CREDS_IV` بسازید. مقدار هر کلید باید یکتا باشد. کلید ارائه‌دهنده را هم در همان فایل قرار دهید. برای ساخت اولین حساب، موقتاً `ALLOW_REGISTRATION=true` کنید.

```sh
docker compose -f compose.nexa.yml -f compose.nexa.librechat.yml up -d
```

پنل LibreChat فقط روی http://localhost:3080 در دسترس است. پس از ساخت حساب و Agent، ثبت‌نام را غیرفعال کنید و سرویس را با همان دستور به‌روزرسانی کنید. در Nexa آدرس مدل را `http://librechat:3080/api/agents/v1/chat/completions` بگذارید و کلید Agent را در فیلد «کلید API مدل» ثبت کنید. این ترکیب برای اجرای Agent است. نصب جداگانه RAG بالادست در فاز بعد ارزیابی می‌شود. تصویر توسعه LibreChat در Compose با شناسه ثابت ثبت شده است.

## رفتار نسخه اولیه

- اولویت تنظیم‌ها کاربر، سپس گروه با اولویت بالاتر، سپس سراسری است. هر گزینه به‌صورت مستقل ارث می‌رسد. در تساوی اولویت گروه، شناسه کوچک‌تر مقدم است.
- «فقط دانش» پاسخ ثبت‌شده یا گزیده فایل مرتبط را مستقیماً برمی‌گرداند. «ترکیبی» گزیده‌های مرتبط را به مدل می‌دهد و در صورت نبود منبع به مدل عمومی رجوع می‌کند. «آزاد» بدون خواندن پایگاه دانش مدل را فراخوانی می‌کند.
- سهمیه بر اساس تعداد درخواست پذیرفته‌شده محاسبه می‌شود. صفر یعنی سقف صفر. مقدار خالی یعنی ارث‌بری و در سطح سراسری یعنی نامحدود. درخواست ناموفق در گزارش ثبت می‌شود اما از سهمیه کم نمی‌شود.
- پاسخ مدل کلمه‌به‌کلمه نمایش داده می‌شود و کاربر می‌تواند آن را متوقف کند. بخش دریافت‌شده با برچسب «ناتمام» ذخیره و از سهمیه کم می‌شود؛ توقف پیش از رسیدن اولین بخش، از سهمیه کم نمی‌شود. بدون JavaScript، فرم به‌صورت عادی ارسال می‌شود.
- هر پرسش در یک گفتگو ذخیره می‌شود. تاریخچه فقط برای صاحب آن قابل مشاهده است و در حالت‌های ترکیبی و آزاد، شش نوبت موفق آخر همان گفتگو همراه پرسش به مدل ارسال می‌شود. حذف گفتگو گزارش فعالیت را پاک نمی‌کند.
- فایل متنی UTF-8 با پسوند TXT یا MD تا ۲۵۶ کیلوبایت پذیرفته می‌شود. هر کاربر حداکثر `NEXA_MAX_PENDING_UPLOADS` فایل در انتظار تأیید (پیش‌فرض ۱۰) می‌تواند داشته باشد. بارگذاری کاربر منوط به سیاست و انتشار برای دانش منوط به تأیید مدیر است. فقط فایل فعال و منتشرشده در دامنه مجاز کاربر یا گروه وارد بازیابی می‌شود.
- لاگ‌ها حاوی متن سؤال و پاسخ و اطلاعات بارگذاری‌اند. پنل Django از نقش‌ها و مجوزهای خود Django برای مدیریت استفاده می‌کند.

در داشبورد مدیریت، مدیر کل می‌تواند با «آزمون اتصال» دسترسی مدل‌های فعال و ورود حساب سرویس AD را بررسی کند. آزمون مدل یک درخواست کوتاه واقعی به سرویس می‌فرستد.
