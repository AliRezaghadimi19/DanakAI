# معماری و فازهای Nexa

## انتخاب پایه

| حوزه | آنچه در LibreChat بررسی شد | تصمیم Nexa |
|---|---|---|
| مجوز | MIT، فایل LICENSE در کامیت پایه | حفظ اعلان‌ها و استفاده از API Agent |
| ورود | ایمیل/رمز و LDAP/AD، تنظیم اتصال در محیط | ورود محلی Django و LDAPS با تنظیم روش ورود، رمز اتصال و CA از پنل |
| ارائه‌دهنده | چند ارائه‌دهنده و endpoint سفارشی، API سازگار با OpenAI برای Agent | آداپتور مشترک برای Agent یا ارائه‌دهنده مستقیم |
| پایگاه دانش | RAG API، PostgreSQL/pgvector در نصب Docker | سؤال‌وجواب و بازیابی واژگانی فایل‌های تأییدشده برای MVP. ارزیابی RAG API در فاز بعد |
| RBAC | نقش و گروه و مجوز منابع | مجوزهای Django Admin و سیاست‌های Nexa پیش از هر فراخوانی مدل |
| فارسی | کاتالوگ fa-IR و گزینه زبان در رابط کاربر | فارسی پیش‌فرض و RTL در رابط اصلی و مدیریت Django |
| سهمیه | اعتبار توکن قابل تنظیم | شمارش همزمان روزانه و ماهانه هر کاربر با ثبت در تراکنش |

Open WebUI قابلیت LDAP و دانش و RBAC دارد. محدودیت نشان تجاری آن در انتخاب پایه برای محصولی با نام Nexa مؤثر بود. [مجوز Open WebUI](https://docs.openwebui.com/license/)

کد بررسی‌شده شامل `client/src/locales/fa`، `api/server/routes/agents/index.js` و `docker-compose.yml` است. [مجوز LibreChat](https://github.com/LibreChat-AI/LibreChat/blob/f4154b649efa37e1345ccc517a4d8d1ed2178c82/LICENSE) · [LDAP](https://www.librechat.ai/docs/configuration/authentication/ldap) · [مدیریت](https://www.librechat.ai/docs/configuration/admin_panel) · [اعتبار توکن](https://www.librechat.ai/docs/configuration/token_usage) · [RAG API](https://github.com/LibreChat-AI/rag-api)

## فازها

1. انجام شده در نسخه محلی. پایه قابل اجرا، مدل داده، مدیریت، ورود، سیاست، سهمیه، فایل متنی و گزارش. SQLite با تراکنش IMMEDIATE برای اجرای تک‌نمونه‌ای. استفاده مجدد از Django برای نشست، CSRF، رمز، RBAC، ORM و رابط مدیریت.
2. باقی‌مانده. پذیرش با AD و مدل واقعی سازمان، نگاشت گروه AD، تست یکپارچه Agent، تاریخچه مکالمه، آزمون کیفیت بازیابی فارسی و ارزیابی RAG API برای اسناد PDF و Office.
3. باقی‌مانده. آمادگی بهره‌برداری با PostgreSQL، پشتیبان‌گیری، سیاست نگهداری لاگ، محدودسازی تلاش ورود در ورودی شبکه، مشاهده‌پذیری، اسکن فایل و آزمون بار و دسترسی. تکمیل ترجمه پیام‌های کتابخانه و بررسی دسترس‌پذیری.

مسیر چت از نشست و سیاست تا رزرو سهمیه در Nexa کنترل می‌شود. LibreChat پشت شبکه داخلی برای اجرای Agent به‌کار می‌رود. داده‌های فایل و تاریخچه کاربر به‌طور خودکار با LibreChat همگام نمی‌شوند.

## وضعیت تحویل محلی

- داشبورد با آمار واقعی و میان‌بر انتشار، پنل مدل و تنظیمات AD، و ثبت رمزنگاری‌شده کلیدها و رمزها آماده‌اند.
- ۱۱ آزمون در Docker پاس شده است. ورود داخلی، سهمیه، کنترل دانش، مسیر LDAPS آزمایشی و ذخیره تنظیمات حساس پوشش دارند. در اجرای محلی، ارتباط داخلی با LibreChat نیز بررسی شده است.
- پذیرش با دایرکتوری واقعی و اجرای پاسخ از مدل یا Agent واقعی هنوز انجام نشده است. گزارش سلامت LibreChat صرفاً دسترسی به سرویس را تأیید می‌کند.
- Docker فعلی روی آدرس محلی منتشر می‌شود و برای دمو و توسعه است. دستورالعمل استقرار سازمانی و آزمون بازیابی پس از انتخاب زیرساخت در فاز سوم تکمیل می‌شوند.
